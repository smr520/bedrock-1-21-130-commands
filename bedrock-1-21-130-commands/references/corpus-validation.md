# 命令语料规范化与训练规则

本页记录如何把 `.mcworld`、BDX 和文本合集转成可用于技能回归的匿名语料。原始世界、完整命令、坐标、玩家名、地图名、结构名和内部价格只留在本地私有目录，不进入 Apache-2.0 发布包。

## 四层证据

| 层级 | 证明内容 | 不能证明 |
| --- | --- | --- |
| 原始存储 | ZIP、LevelDB `.log/.ldb` 或 BDX 中存在某些字节和写入历史 | 这些记录仍是当前方块、语法正确或游戏里能执行 |
| 当前世界状态 | 按 LevelDB sequence、墓碑和选区边界还原后的现有命令方块 | 网易客户端实际存在该命令参数 |
| 静态语法 | 命令通过项目 linter、链检查和 JSON 检查 | 客户端加载、红石、区块和多人路径正常 |
| 实机运行 | 已在指定网易版本、设备和世界上下文执行 | 自动适用于其他渠道或版本 |

语料训练必须始终写明所处层级。地图保存过一条命令，只能标为 `corpus-observed`。

## `.mcworld` 规范化

审计已有世界时按以下顺序处理：

1. 只读检查 ZIP 路径、大小、解压上限、`level.dat` 和 `levelname.txt`。
2. 从世界名或文件名读取 `@[起点]~[终点]`，所有方块实体都要再按该选区过滤。相邻区块可能保存选区外一格的实体。
3. 解析写前日志和 `.ldb` 表。日志内每个操作按批次起始 sequence 递增；表内内部键末尾 8 字节拆成 sequence 与 value type。
4. 同一 user key 只保留最高 sequence；删除记录形成墓碑，不得让旧表重新复活已删除内容。
5. 只从合并后的当前有效键中解析方块实体和子区块调色板。
6. 将命令方块实体坐标与当前子区块方块交叉核对，分别统计物理方块、空气坐标孤儿和类型未知。
7. 把完整命令写入私有临时目录，随后运行 `validate-commands.mjs --channel netease`。
8. 导出公开材料前删除玩家名、绝对坐标、地图标语、内部目标名、价格、结构名和原始命令。

直接读取每个 `.log` 写入批次会把历史版本当成独立方块，造成重复计数。只读 `.log` 又会漏掉已经压实进 `.ldb` 的命令。两者必须按 sequence 合并。

## BDX 规范化

- 先确认 `BD@` 外层头和解析器来源，再解析 Brotli 内的操作流。
- 命令方块可能藏在通用 NBT 方块操作中；只检查传统命令方块操作码会漏命令。
- 同一个方块可能先放置、后设置命令数据，最终状态以最后一次操作为准。
- BDX 中的 `structure load` 名称通常不随文件提供。没有依赖清单时，不能称为自包含投影。

| 信号 | 样本数 | 训练解释 |
| --- | ---: | --- |
| 单条命令含至少 3 个选择器 | 2,410 | 深入 `execute` 前必须检查执行分叉，不能只数命令方块 |
| `structure load/save` | 679 | 世界依赖外部结构时，交付必须列结构名和缺失后的行为 |
| `setblock` | 337 | 常见于机关重置、清文件和动态命令方块；要检查坐标依赖、重进恢复和字符串转义 |
| 传送 | 315 | 检查目的地是否单一目标、是否安全落点、是否会重新触发 |

## 训练判定

### 正向吸收

- 选择器 `scores`、`hasitem`、`tag`、`type`、`r` 和朝向条件可以直接融合检测与动作。
- 固定间隔任务用延迟循环根；长期状态用每条玩家分数，不依赖最近玩家。
- 成功、失败和取消路径都要清理临时标签；计分板状态按模块命名。
- 初始化的 `objectives add`、`gamerule`、`tickingarea add` 集中到一次性脉冲或聊天栏准备步骤。
- 小菜单、注册、签到、随机传送和简洁状态机优先作为教学结构。

### 需要审查

- 一个文件只有 4 至 7 条唯一命令，却有 92 至 229 个命令方块。它们可能是重复模板、独立区域触发器或延迟错峰；先按触发位置和运行时刻分类，再决定是否共享根。
- 精确命令相同不表示可以合并。两个不同按钮、不同队伍区域或不同延迟槽位可能故意重复同一文本。
- 多条命令含三个以上选择器时，优先减少 `as/at` 的笛卡尔积，而不是把更多条件塞进一层。
- 大量空命令方块仍是真实物理占用，不能从维护预算中消失。
- 大量外部 `structure load` 必须先交付结构依赖清单。纯方块链只解决控制逻辑，不能内嵌缺失结构。

### 反例保留

- 历史写入回放导致的重复计数。
- 没有边界过滤而混入选区外实体。
- `objective` 分散创建、循环里重复设置游戏规则。
- `run/` 粘连、坏 rawtext JSON、`replaceitem` 组件错误和全角语法符号。
- 高重复但缺少触发归属说明的“方块墙”。

## 外部校验器

本地 `WaterStructure` 快照（模块路径 `github.com/Yeah114/WaterStructure`）可作为当前世界状态的独立开发期校验器。本项目只使用它验证计数和选区行为，不把源码或组合二进制打进 Apache-2.0 发布包；该快照声明 AGPL-3.0，分发组合程序时许可证义务不同。

[TriM-Organization/BDXConverter](https://github.com/TriM-Organization/BDXConverter) 可用于外部只读 BDX 核对，采用 MIT，但也不是本 skill 的运行依赖。

审计器与外部校验器在本轮 20 个世界上对照了命令实体、物理命令方块、孤儿实体、空命令和非空命令，全部一致。该结果只证明格式回读一致，不证明网易客户端运行通过。
