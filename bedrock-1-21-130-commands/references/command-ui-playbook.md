# 纯命令 UI 设计与会话验收

`tellraw`、`titleraw`、`title` 和侧边栏只负责显示与反馈，不能变成真正的模态窗口。玩家仍能移动、攻击、死亡、换维度或离线，所以每次确认都必须重新验证状态。

## 输出通道

| 通道 | 适合 | 避免 |
| --- | --- | --- |
| `tellraw` | 详细列表、价格、失败原因、交易历史 | 每 tick 刷新大 JSON |
| `titleraw actionbar` | 一行或少量短状态、当前选择 | 长菜单、连续按 tick 重发不变内容 |
| `title` / `subtitle` | 阶段切换、关键成功/失败提示 | 连续浏览和持续 HUD |
| 侧边栏 | 排行榜、稳定阶段列表 | 一次性确认和临时错误 |

详细说明放 `tellraw`，动作栏只保留最关键的短句。多个 HUD 共存时必须走单一仲裁链；完整示例见 [hud-arbiter.md](../examples/hud-arbiter.md)。

## 状态与生命周期

菜单至少定义：

```text
IDLE → OPEN → SELECTING → VALIDATING → SUCCESS / FAILED → CLOSE
```

- `OPEN` 只设置菜单编号和操作锁，不代表选择已经成功。
- `SELECTING` 只改变当前编号；显示高亮不能替代状态写入。
- `VALIDATING` 重新检查在线、分数、物品、距离、权限、冷却和交易锁。
- `SUCCESS`/`FAILED` 给出文字反馈，再进入关闭或重试。
- 所有终止路径都清理选择标签、临时分数、锁和一次性确认标记。

玩家死亡、重生、传送、换维度、断线重进或动作栏被更高优先级系统占用时，菜单必须能回到可解释状态。

## 交互方式

纯命令没有可靠的鼠标悬浮、点击吸收或手柄焦点，不要设计只有鼠标悬停才能发现的功能。按钮、压力板、丢指定物品和抬头/低头都应在目标设备上验证。

至少提供一种明确退出方式，例如：

- 低头关闭；
- 丢指定物品关闭；
- 固定取消按钮；
- 输入明确的关闭选项。

“退出”不能只清一个显示分数而留下操作锁。危险操作或扣费交易应先显示完整目标、价格和失败原因，再做一次确认。

## 状态表达

- 不只依赖颜色。同时使用 `[当前]`、`[锁定]`、`[失败]`、前缀、括号或符号。
- 锁定状态要说明原因，例如“金币不足”“背包已满”“目标离线”“冷却中”。
- 菜单打开后保持低频刷新；状态没变化时不要每 tick 重发相同大文本。
- 长文本拆成短行；重要名称至少完整显示一次，不能在确认环节只显示缩写。
- `%%2` 条件 T 显可减少只读显示分支，但只改变文字，不替代状态机或事务。见 [conditional-rawtext.md](../examples/conditional-rawtext.md)。

## 多人会话

命令 UI 没有输入吸收，后按按钮的玩家可能改变共享状态。涉及扣费、清物、领奖、传送或商店时：

1. 先锁定单一操作者。
2. 在确认前重新验证操作者仍在线且满足条件。
3. 成功后一次性结算，失败路径无条件清理锁。
4. 两人同 tick 操作时，不得共用含义不同的中间标签或分数。

## 验收清单

- [ ] 当前选择有文字或符号标记，不只靠颜色。
- [ ] 每个锁定项显示可理解的失败原因。
- [ ] 至少有一种明确取消/退出方式。
- [ ] 成功、失败、取消都会清理菜单和操作锁。
- [ ] 死亡、重生、传送、换维度后不会卡在隐藏菜单状态。
- [ ] 触摸、键盘和手柄都有可发现的触发方式。
- [ ] 两人同 tick 操作不会串号或重复结算。
- [ ] 状态不变时没有每 tick 重发大 JSON。
- [ ] `tellraw`、动作栏、标题和侧边栏职责没有冲突。
- [ ] 所有显示字段都有对应计分板、标签或在线验证来源。

资源包 JSON UI、Python `ScreenNode`、`ViewBinder`、可点击控件和原生界面修改不属于本 skill 的纯命令方块边界。若用户明确需要这些能力，应另建资源包/脚本方案并单独管理许可证与实机测试。
