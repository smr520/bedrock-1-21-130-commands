# 复杂命令系统：先建模，再摆方块

本页用于多条链、持久状态、多人事务、队列、数据化 HUD、计时器或大型地图系统。单条命令的语法问题直接给修复，不需要套完整设计流程。

## 1. 先写行为契约

复杂系统至少写清六项：

```text
谁触发：
起始状态：
成功结束状态：
失败结束状态：
重置方式：
玩家退出、死亡、旁观或换维度时：
```

多人系统再补两项：状态是全局还是每玩家，同一 tick 两人触发时谁先、谁后、是否允许并发。

行为契约没定清楚时，不要先摆 `execute as @a`。一条看似能跑的链通常会在重复触发、玩家退出或失败路径里留下脏标签。

## 2. 选择计算模型

| 需求形状 | 模型 | 纯命令方块实现 |
| --- | --- | --- |
| 有明确阶段，可开始、暂停、结束 | 有限状态机 | 全局或每玩家 `dummy` 分数保存阶段 |
| 多个输入汇成一个结算 | 数据流 / 事务 | 输入 → 校验 → 扣费 → 发奖 → 无条件清理 |
| 按先来后到处理有限条目 | 队列 / 环形缓冲 | `q_head`、`q_tail`、`q0..qN` 假玩家 |
| 后进先出 | 栈 | `q_sp` 指针和固定槽分数 |
| 需要射线、圆、体积或成批实体 | 树 / 空间采样 | `as`、`at`、`positioned`、`rotated` 分叉加预算 |
| 定时、延时、取消和并行 | 调度器 | 每 tick 递减的分数或命令方块延迟 |
| 多条路径逐步传播 | 图 | 固定节点表、访问标记和队列 |

常见命令模型不是互斥的。例如撤离系统通常是“每玩家状态机 + 全局时钟 + 一次性奖励事务”。

## 3. 设计状态表

| 状态 | 载体 | 归属 | 类型 / 范围 | 初值 | 谁写 | 谁读 |
| --- | --- | --- | --- | --- | --- | --- |
| `menu` | 记分板 `ui` | 每玩家 | `0..6`，0 为关闭 | `0` | 菜单链 | 显示与确认链 |
| `arena_state` | 记分板 `arena` | 假玩家 | `0=idle, 1=count, 2=run` | `0` | 开始/结束链 | 时钟与显示 |
| `tx_shop` | tag | 玩家 | 布尔临时锁 | 无 | 购买入口 | 扣费、清物、发奖 |
| `join_epoch` | 记分板 `join_epoch` | 每玩家 | `0..1` 临时事件 | 无 | 进服链 | 欢迎动作 |

状态载体只有四种基本选择：

- `dummy` 分数：整数、倒计时、编号、队列槽、全局变量。
- tag：布尔状态、临时选人锁、实体分组。
- 方块或实体：空间索引、结构模板、持久容器。
- 命令方块：只负责逻辑，不能把它当可运行时改写的变量内存。

内部名优先使用 ASCII，例如 `ui`、`coins`、`cd_attack`、`tx_shop`。中文名称适合显示，不宜依赖在长期内部状态里。

## 4. 分阶段排链

纯命令方块链用同一套阶段划分：

```text
INPUT → VALIDATE → TRANSITION → OUTPUT → CLEANUP
```

- `INPUT`：检测按钮、区域、物品、视角、实体或时间。
- `VALIDATE`：检查在线、分数、库存、容量、冷却和并发锁。
- `TRANSITION`：扣分、清物品、改状态、打标签。
- `OUTPUT`：给奖励、传送、播放音效、生成实体或显示文本。
- `CLEANUP`：清除临时标签、撤销锁、复位一秒脉冲、删除失败分支留下的中间状态。

清理块默认用无条件连锁。需要阻止后续动作时，把完整条件写进下一块的 `execute if/unless`，不要依赖“条件失败会自动截断整条链”。

## 5. 幂等、原子性和可重置

复杂系统至少检查四个不变量：

1. **幂等**：同一按钮被持续供能、重复点击或同 tick 重入时，不能重复发奖。
2. **原子性**：扣费、清物、发奖和状态切换不会在失败路径只完成一半。
3. **有界**：队列长度、数组下标、倒计时、实体数量和执行分叉都有上限。
4. **可复位**：状态、tag、界面、临时实体和中间分数都能回到初始值。

交易事务通常必须先锁对象，再修改资源：

```text
选人并加 tx 标签
→ 校验库存和余额
→ 扣分
→ 清物品
→ 发奖励
→ 无条件清理 tx
```

单人操作区可以省略锁，用连续 `@p[r=3]` 减少方块；多人共用按钮不能接受中途换人时，必须保留锁定格。

## 6. 常用控制模式

### 每 tick 时钟

一个全局循环根递增 `tick`，每到 20 复位为 0。多个每秒动作共用这条根，不要每个系统各建一个 20 Hz 循环块。

### N 分频

循环方块直接设 `延迟20`、`延迟100` 可以省掉计数器。需要暂停、显示或重置时，再用 `tick` 分数。

### 一次性脉冲

用计数器的“到达条件”生成一 tick 事件，例如每秒只在 `tick=0` 时执行。显示、扣血和奖励都读取同一事件分数，避免链中途改值导致后续选择器失效。

### AND / OR / NOT

- AND：一条 `execute` 连续写多个 `if`。
- OR：各分支先把同一个 flag 设为 1，再由后续链读取并清理。
- NOT：使用 `unless`。空选择器在 `if entity` 下失败，在 `unless entity` 下成功。

### 状态机

每个状态只做一件事，并写清进入和退出动作。切换状态后，后续仍依赖旧状态的动作应立即停止，或先把对象打成临时 tag。

### 队列

基岩版没有动态数组。固定槽队列用整数指针和条件分支逐槽赋值，必须处理满、空、回绕和重复入队。

### 分叉

`execute as @a at @a` 的实例数是来源数乘目标数。减少命令方块前先算最大实例：

```text
每次触发实例数 = 来源匹配数 × 目标匹配数 × 后续动作数
每秒实例数 = 每次触发实例数 × 每秒触发次数
```

## 7. 数学与显示

- 计分板只有整数。百分比通常先乘后除，并在每一步钳制。
- 坐标和几何计算优先预生成整数偏移表，不在命令里寻找浮点表达式。
- 距离优先用选择器 `r` / `rm`；精确的小范围判定再比较预计算距离平方。
- 显示层不是状态源。状态写入一次，显示链按 5–10 Hz 读取。
- 普通标题、动作栏、聊天和大 JSON 面板有不同大小与覆盖风险；多系统共用动作栏时先设优先级。

## 8. 结构化 spec

多链方案可以写成 JSON：

```json
{
  "name": "example",
  "channel": "netease-china",
  "targetVersion": "1.21.130",
  "commandsOnly": true,
  "blocks": [
    {
      "id": "B1",
      "type": "repeat",
      "condition": "unconditional",
      "redstone": "always_active",
      "delay": 0,
      "command": "scoreboard players add .tick timer 1",
      "next": null
    }
  ],
  "tests": ["单次执行", "区块卸载", "两名玩家同时触发"]
}
```

字段定义见 [chain-spec.schema.json](../assets/chain-spec.schema.json)。运行：

```powershell
node scripts\validate-chain-spec.mjs 你的文件.json --write 构建表.md
```

spec 只记录可验证结构，不能证明目标网易客户端已经实机通过。

## 9. 交付时的最小证据

复杂方案至少报告：

- 渠道、版本和是否使用附加包。
- 状态表与失败/重置路径。
- 方块总数和共享模块后的实际总数。
- 每个高频链的触发频率和最大执行分叉。
- 哪些命令是官方确认、客户端确认、语料观察到或仍未验证。
- 已完成的静态检查和仍需实机测试的路径。
