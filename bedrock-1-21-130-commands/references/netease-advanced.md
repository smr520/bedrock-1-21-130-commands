# 网易高级纯指令能力

本页只在用户明确需要 FMBE/MBE、数据化 RPG、武器技能、UID、二进制坐标或大型地图框架时读取。基础菜单、商店和计分板问题先看 [systems.md](systems.md) 与 [selectors-and-scoreboard.md](selectors-and-scoreboard.md)。

## 1. FMBE / MBE

FMBE 和 MBE 是用原版实体加 `playanimation`、Molang 变量和手持物品制造的客户端显示模型。

| 类型 | 常见载体 | 显示层 | 代价 |
| --- | --- | --- | --- |
| FMBE | 狐狸 | 主手物品 | 一模型一实体，需处理 AI、声音和固定锚点 |
| MBE | 盔甲架 | 副手物品 | 命令可能更少，但有碰撞箱和实体成本 |
| 多部件模型 | 多个狐狸或盔甲架 | 每部件一只实体 | 初始化长、性能高、需要视觉校准 |

网易官方命令表明确有 `playanimation`，可以进入纯命令方块方案。具体动画名、Molang 控制器、变量单位和枢轴属于 `community-doc`，必须按目标客户端实测。

工程规则：

- 显示实体是客户端视觉，不是真实方块、碰撞体或红石导体；不能用 `if block` 检查。
- 一个模型部件默认对应一个实体。先列部件表，再算实体数、命令数、刷新频率和常加载区。
- 固定位置和模型选择优先使用绝对体积或明确锚点。命令方块离展示区很远时，不要误把 `r=` 当成相对模型。
- 多部件模型应分别站在真实部件中心，再设置局部偏移；把大量部件堆在同一点后只靠动画偏移容易产生枢轴错位。
- 多实体初始化链应分段，初始化后先计数“实体数 = 唯一 tag 数”，再启用玩法。
- 动画变量若高频写入，先降到 1 Hz 或事件刷新；每 tick 只保留必要的锚定和命中检测。
- 远处结构使用 `tickingarea`，结构加载后重新打 tag、施加效果并检查模型。
- 功能可以通过静态检查和实体计数验证，外观仍需要目标网易客户端截图。

## 2. 数据化 RPG

数据化系统的稳定结构是：

```text
基础属性
+ 装备加成
+ Buff / 职业加成
= 最终属性
→ 伤害 / 治疗事务
→ HUD / 血条 / 等级
```

- 基础值持久，只在创建、升级或洗点时写入。
- 装备层可每 tick 或低频清零后由 `hasitem` 重建。
- Buff 层单独保存剩余时间与数值。
- 最终属性只读，动作链不要把它写回基础值。
- 伤害事务开始清临时分数，结束无条件清 tag。一次攻击只结算一次。
- 显示层限频；动作栏、侧边栏和标题各自只有一个可见状态。

生命、攻击、防御、经验和金币都是自建 `dummy` 状态。普通原版攻击不会自动同步真实伤害或生命值。

### 真实受击的边界

网易地图语料里常见几类做法：

| 方法 | 能证明什么 | 风险 |
| --- | --- | --- |
| 最近实体 + 距离 | 目标在附近 | 不证明这一下真实命中，多人时可能选错 |
| 手持物品 + 冷却 | 玩家可能正在攻击 | 不读取真实受击事件 |
| 钓鱼钩、箭或投射物实体 | 某个投射物存在或落地 | 发射者归属需要额外状态，拥挤时易误判 |
| 1 耐久护甲 / 装备槽探针 | 槽位在上一刻被破坏，可近似一次受击 | 属 `corpus-observed`，槽位、组件和成功次数必须在网易目标客户端实测 |

任何真实受击技巧都要分别测试普通攻击、暴击、远程、持续伤害、旁观、死亡、切维度和同 tick 多次命中。

## 3. 武器与技能触发

网易语料常见武器触发器包括手持物品、钓鱼钩、箭、雪球、盔甲架和粒子路径。纯命令方块更稳的结构是：

```text
入口检测 → 锁定施法者 → 检查冷却/消耗 → 选目标 → 结算效果 → 清理
```

- 不要用“附近有玩家/实体”直接当作技能命中。
- 钓鱼钩和其他投射物在没有资源包或脚本时通常无法可靠取得发射者；位置和最近玩家只是近似。
- 每把武器的冷却、消耗、倍率和目标上限独立保存，避免多种武器共用临时分数。
- 射线用嵌套 `positioned` / `rotated` 时，先算最大分叉次数和每 tick 成本；减少方块不代表减少服务器执行量。

## 4. UID、数组与二进制坐标

大型系统常用唯一编号把玩家、装备、菜单项和传送点关联起来：

- UID 分配链必须是单目标，并处理迟到玩家、离线记录和重置。
- 固定数组用 `q0..qN` 假玩家和指针模拟，检查满、空、回绕和重复入队。
- 二进制或十进位坐标分解只适合固定世界边界、固定单位和完整范围测试。超出坐标范围会被钳制或漂移。
- 传送链要计算相对坐标倍率、维度换算和加载区块，不能只验证数字相减。

## 5. 菜单、商店和结构

- 菜单状态是整数分数，显示是 `title` / `titleraw`，视角确认用 `rx` / `rxm`。
- 商店交易先锁定玩家，再校验库存、扣分和清物；失败路径必须无条件清理锁。
- `structure load` 适合带方块实体和实体的模板，`clone` 适合纯方块；重载后重新初始化临时状态。
- 每 tick `titleraw @a`、全图 `@e`、大范围 `fill`/`clone` 和多个 20 Hz 根都需要性能预算。

## 6. 网易高级方案验收

| 层级 | 必测 |
| --- | --- |
| 命令 | `/help`、目标客户端补全、最小执行 |
| 实体 | 数量、唯一 tag、物品、位置、区块加载 |
| 状态 | 初值、成功、失败、重入、重置 |
| 多人 | 同 tick、挤近、死亡、旁观、换维度、离线和重进 |
| 表现 | actionbar 覆盖、声音、粒子、镜头和 FMBE 截图 |
| 性能 | repeat 根数、实体数、选择器范围、分叉数、HUD/动画刷新频率 |

没有目标客户端结果时，只写 `static-only` 或 `corpus-observed`。外部仓库或样例地图出现过某条命令，不等于当前网易客户端已经验证。
