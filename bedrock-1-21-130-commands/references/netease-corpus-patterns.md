# 网易指令语料：可吸收模式与反模式

本页来自用户提供的工作区语料抽查，不代表任何第三方教程许可。语料只用于发现结构和反模式；发布包不包含原始压缩包、地图、截图、作者名、群号或整段第三方命令。

## 2. 高频结构

### 执行与状态

- `execute` 是动作分发核心。
- `scoreboard` + `tag` 承担绝大多数状态。
- 中文 objective 很常见，但长期维护时优先转换成 ASCII 内部名。
- 数据化系统通常把“基础值、装备、Buff、最终值、事务、显示”混在同一组多链中，稳定方案应分层。

### 菜单与 HUD

- `title` / `titleraw` 搭配菜单编号分数。
- 抬头和低头通过 `rx` / `rxm` 检查。
- 动作栏承载多行 T 显，但多个系统同时输出会互相覆盖。
- 大量菜单靠雪球、鸡蛋、纸或鱼钩建立事件入口，落点只能近似归因。

### 武器和投射物

- 手持物品通过 `hasitem` 和槽位选择器识别。
- 钓鱼钩、箭、雪球、盔甲架和粒子常被用作射线或命中探针。
- `damage` 在真实语料中出现，但命令存在性和伤害来源仍需目标客户端验证。
- 多把武器共享临时分数时，容易发生冷却、倍率和目标归属串线。

### 结构与常加载

- `structure save/load` 用于复制带方块实体的模板。
- `clone` 用于纯方块或小机关。
- `tickingarea` 是远处机关持续运行的关键；添加后必须测命令方块所在区块和结构区域。

## 3. 语料中反复出现的反模式

| 反模式 | 后果 | 新交付规则 |
| --- | --- | --- |
| 旧 `execute @a ~ ~ ~ ...` | 新版本解析失败 | 改成 `as` / `at` / `run` |
| 旧方块 data 参数 | 新方块状态不匹配或行为漂移 | 改成方块状态并实机验证 |
| 没初始化就读取分数 | 选择器或比较结果不稳定 | 用 `add ... 0` 建分数或明确测试未跟踪行为 |
| 先改菜单/交易状态再检查 | 后续选择器找不到原对象 | 先 tag 锁定，再修改状态 |
| `@a` 对全局中间量做赋值 | 多人互相覆盖 | 使用每玩家分数、`c=1` 或明确单人区域 |
| 每次操作弹出大标题 | 覆盖、刷屏、遮挡玩法 | 菜单优先动作栏，标题只用于关键节点 |
| 每个功能一个 repeat 根 | 全时运行负载叠加 | 共用轻量循环根，按事件门控 |
| 每个价格或配置项一个命令方块 | 65 个循环方块只改一个价格分数，修改和维护成本高 | 先建模数据载体；固定映射可优先放入选择器、物品组件或分层状态，再对实际触发频率做测量 |
| 先 `fill`/`clone` 复制再留下空格 | 实图里会出现大量看似存在、实际无命令的方块 | 世界审计报告空命令、无效果重复和孤立循环；交付清单只统计有效系统格 |
| `run/command`、`]run command` 等粘连 | 命令无法按预期拆分执行 | 用词法边界检查 `run` 前后空白，不把“地图里出现过”当作可运行证据 |
| 旧参数与混合组件 JSON 同时出现 | 编辑器可保存，目标版本可能拒绝或改变语义 | 先按当前命令签名逐条重写；不要只替换命令首词 |
| 附近有目标就当命中了 | 误判、多人抢目标 | 使用真实事件探针或明确限制为近似玩法 |
| 复制作者署名、群号和截图 | 敏感信息和许可风险 | 只匿名提炼模式，不随发布包分发 |

## 4. 文件编码与导入

抽查发现部分旧文本可能不是 UTF-8。直接读取出现替换字符时：

1. 把原文件标记为编码待确认。
2. 不把乱码命令复制进正式示例。
3. 用原编辑器或编码检测工具确认 GBK/UTF-8。
4. 转换后再次扫描 `U+FFFD`、全角语法符号和旧 `execute`。
5. 编码修复后仍需逐条重写，不把二进制或文档截图当作可执行命令。

## 5. 从语料迁移到 2.0

迁移一个旧网易系统时按以下顺序：

1. 识别触发、状态载体、输出和清理。
2. 把旧 `execute` 转成新语法，保留原本的“谁 / 在哪 / 何时”。
3. 把旧数据值、全角标点和乱码修成目标版本语法。
4. 每个全局中间量检查多人覆盖和同 tick 重入。
5. 把动作栏、标题、粒子和声音移出高频状态机。
6. 运行命令校验、链级校验、结构化 spec 校验和网易渠道校验。
7. 在网易 3.10 / BE1.21.130 客户端测试，记录设备、渠道和结果。

## 6. 证据边界

语料中的下列内容不能自动升级为官方事实：

- `damage`、`titleraw`、`hud` 的具体可用版本。
- `replaceitem ... keep` 或耐久护甲探针。
- `netease:` 专用实体、粒子和组件参数。
- 中文 objective、`@n`、`haspermission`、`has_property`。
- 超过 512 字节的标题、超大 JSON、复杂 FMBE 动画变量。
- 旧地图里的坐标、结构名、作者数据和服务器设置。

`.mcworld` 中的命令方块实体证明该命令被保存进了地图，不能证明它在当前网易客户端能成功解析或已经运行。语料审计应把“地图存在”“静态语法通过”“目标客户端执行成功”分成三个证据等级。原始世界如果是他人作品，除非有明确许可，不进入 Apache-2.0 发布包。

从实图提炼训练材料前，至少移除玩家名、服务器标语、地图名、绝对坐标、结构名、内部价格、专属目标名和完整 rawtext。发布包只保留结构化模式、方块预算和经过重写的示例；本地完整报告和命令导出一律标为私有审计产物。

这些项目必须保留 `corpus-observed` 或 `unverified` 标签，直到网易目标客户端给出 `/help` 或执行结果。
