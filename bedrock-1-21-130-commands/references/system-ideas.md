# 可继续实现的系统

本页只列可复用的玩法方向、预算和原版限制。方块数是精简原型估算，聊天栏一次完成的目标创建计 0 格；多人保护、跨区块恢复和边界提示会额外增加方块。

## 公共模块

| 模块 | 建议预算 | 关键约束 |
| --- | ---: | --- |
| 玩家首次进入 | 3 | 记分板能识别“当前世界第一次记录”，不能可靠识别每次重新登录 |
| 多字段 HUD | 1 | 一条 `titleraw` 可组合多个分数，只有一个动作栏 |
| 动作栏仲裁 | 3 | 多状态共用一条调度链，按优先级只显示一项 |
| 每技能冷却 | 2 | 状态独立，递减动作可接在同一条循环链 |
| 多人交易锁 | 5 | 打标签、扣费、清物、发奖、清标签 |
| 玩家档案与等级 | 4–8 | 经验、等级和奖励阈值主要用分数状态机 |

## 高复用玩法

### 金币商店

目标：余额、购买、回收、查余额。单人操作区可做到 6 格；多人共用按钮应使用临时标签，预算通常再增加 2–4 格。条件优先写进 `hasitem` 和 `scores` 选择器。

### 撤离模式

目标：进入方块区域后累计，离开归零，达到阈值传送并领奖。基础版约 5 格；多阶段提示、失败路径和多人奖励会继续增加。撤离进度应接入动作栏仲裁，避免与普通 HUD 冲突。

### 开箱与签到

目标：随机奖励、保底、钥匙、冷却和累计签到。开箱约 8–14 格，冷却签到约 4–10 格。“每日”只能表示自定义游戏日或累计在线时间，不能只靠纯命令方块精确对应现实自然日。

### 通用弹丸判决

目标：为箭、雪球、鱼钩或烟花落点建立归属、命中检测和一次性结算。核心约 8–12 格。投射物与发射者之间没有可靠的玩家字段，通常需要标签、记分板或位置近似，拥挤区域会误判。

### 武器技能框架

目标：手持物品、冷却、消耗、范围和效果共用一套入口。每把简单武器约 4–12 格。把几十个 `positioned` 或排除选择器塞进一格能降低 CB 数，但解析成本、维护成本和对齐坐标的风险会显著上升。

### 模拟血条与 BOSS

目标：分数血量、阶段、技能计时、死亡奖励和实体清理。玩家血条约 4–8 格，BOSS 约 12–30 格。纯指令不能直接读取任意实体的真实生命值，普通攻击也不会自动同步到模拟分数。

### 倒地与救援

目标：死亡前进入倒地、限制视野或移动、邻近救援和超时淘汰。约 12–24 格。要同时在键盘鼠标和触屏操作上验证 `inputpermission`、摄像机和状态恢复。

### 在线选人

目标：给在线玩家编号，再接入传送、邀请或奖励。五到八人的原型约 8–20 格。编号变化、离线、重名和并发操作都需要额外状态清理。

### 自定义合成与词条

目标：识别配方、品质、属性、强化和回收。固定配方约 10–20 格；完整随机词条通常超过 20 格。需要保存任意物品数据时，往往要同时交付结构、容器或漏斗矿车代理；只有命令文本不能独立完成全部逻辑。

### 区域限制

目标：检查坐标方块、权限标签和允许动作。小范围约 3–8 格。玩家移动范围越大、拦截行为越多，选择和坐标检查成本越高。

## 谨慎实现

| 需求 | 原因与处理 |
| --- | --- |
| 反作弊 | 纯指令只能读位置、方块、背包和分数快照，无法形成服务端权威判定；适合记录可疑状态供人工复核 |
| 天气读取 | 基岩版不能直接 `execute if weather`；只能记录是哪个机关切换了天气 |
| 现实自然日 | 循环延迟和在线分数是游戏内累计，不是可靠的现实日期 |
| 任意物品数据 | 原版命令不能像 Java NBT 一样读写全部物品属性 |
| 领地完整保护 | 固定区域边界可以做，拦截所有破坏和作弊需要覆盖大量动作，不能等同服务端保护 |
| 离线物品邮箱 | 需要可持久保存物品的容器或结构代理，并处理重进、覆盖和容量边界 |

## 选择顺序

先做可由静态检查正确验证的单人功能，再接多人共用按钮、跨区块、重进、满背包和并发交易。每轮只选 5–8 个与当前需求直接相关的方向，不从本页一次实现全部系统。
